# 教材追加ガイド

原稿は`src/data/dayNN.json`に変換します。PDFやWordの自動解析はVer.1の範囲に含めていません。本文を段落に分けてJSONへ転記するだけで、専用の画面を増やさず収録できます。

## 最小の追加教材例

以下は教材ファイルの形式の見本です。既存のDay 1〜14の教材を更新する場合に参考にしてください。実際に編集するときは、公開済みの教材ファイルをベースにします。

```json
{
  "schemaVersion": 1,
  "id": "day02-example",
  "day": 2,
  "title": "追加教材の見本",
  "subtitle": "ここに教材の紹介文を入れます。",
  "minutes": 15,
  "objectives": ["学習後にできることを記述します"],
  "sections": [
    {
      "id": "d2-s1",
      "title": "学習の進め方",
      "paragraphs": ["講義を読み、確認テストで理解を確かめましょう。"],
      "keyPoint": "間違えた問題は復習画面から振り返れます。"
    }
  ],
  "questions": [
    {
      "id": "d2-q1",
      "category": "学習方法",
      "sectionId": "d2-s1",
      "prompt": "このアプリで間違えた問題を振り返る画面はどれですか。",
      "choices": ["復習", "端末設定", "インストール案内", "ブラウザの履歴"],
      "correctIndex": 0,
      "explanation": "復習画面には、最新の確定回答が不正解の問題が集まります。"
    }
  ]
}
```

## フィールドと規則

| フィールド | 規則 |
| --- | --- |
| schemaVersion | 現在は`1` |
| id | 教材固有のID。全教材で一意 |
| day | 1〜14の整数。各日に1教材 |
| minutes | 目安学習時間。正の整数 |
| objectives | 1つ以上の学習目標 |
| sections | 1章以上。章IDは全教材で一意（読了管理に使用） |
| paragraphs | 段落ごとの文字列配列。HTMLやMarkdownは実行・解釈せず文字列として表示 |
| keyPoint | 章末の重要ポイント |
| questions | 1問以上のオリジナル問題 |
| category | 分野別集計のキー。同じ分野は表記を統一 |
| sectionId | この教材内に存在する章のID |
| choices | 空でない4つの異なる文字列 |
| correctIndex | 0〜3の整数。A=0、B=1、C=2、D=3 |
| explanation | 正解の理由と、必要なら他の選択肢が誤りである理由 |
| sources | 任意。資料名 `title` と HTTPS の `url` の一覧。講義末尾の「参考資料」に表示 |

問題IDは**全教材を通して一意**にします。章IDも全教材で一意にしてください。文章の修正では既存IDを維持し、別の問題に差し替える場合は新しいIDを振ります。既存のIDを異なる意味で再利用すると過去の回答・復習が別の問題に結び付いてしまいます。

## 図解

章に任意の`diagram`を指定できます。項目は2つ以上です。`kind`は`flow`（標準）または`nested`（包含関係のインデント表示）を指定できます。

```json
{
  "title": "活用の流れ",
  "items": [
    { "label": "指示を入力", "detail": "目的と条件を伝える" },
    { "label": "生成結果を確認", "detail": "正確さや偏りを点検する" },
    { "label": "活用", "detail": "人が判断して使用する" }
  ]
}
```

## 原稿を取り込む手順

1. その日のタイトル、目標、目安時間を決める。
2. 原稿の見出しを`sections`、各段落を`paragraphs`に分割する。
3. 各章の要点を`keyPoint`にまとめる。必要な図解を追加する。
4. 公式問題の無断転載を避け、独自の4択問題を作る。
5. 各問題に分野名、関連章ID、正解、解説を付ける。
6. `npm run validate:content` → `npm test` → `npm run build`。
7. スマートフォン幅で文章量と改行を確認し、公開する。

JSON Schemaは`docs/course.schema.json`で、エディタの補完・検証に使えます。スキーマを再生成する場合は`node --import tsx scripts/export-schema.ts`を実行します。ID重複、章への参照、選択肢重複などの関連チェックは実行時・検証スクリプトが追加で行います。

## 更新時の履歴

新しい問題を追加すると、旧テストだけではその日の達成条件を満たさなくなります。削除された問題の過去の成績は残り、復習対象からは除外されます。削除問題の解説は「教材更新前の問題」と表示します。テスト途中の問題が削除された場合、履歴を残したまま新しく開始する案内を表示します。

公開済みアプリは更新通知を出します。利用者が更新を適用するまではキャッシュ済みの教材を使い続けます。
